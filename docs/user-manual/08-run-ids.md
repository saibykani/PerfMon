# Run IDs

Every test execution in Perfmon is identified by a Run ID, a short, human-readable key such as `PF-2026-10-06-000127`. The Run ID is the thread that ties everything together: live metrics, JTL imports, HTML reports, logs, events, SLA results, regressions, insights, reports and audit entries all reference it. You pass it to JMeter, quote it in tickets and chat, and use it in every API call about the run.

## Purpose

| Purpose | How the Run ID is used |
|---|---|
| Correlation | Load generators, CI jobs and collectors attach the Run ID to every data point, so data from different tools ends up in the same run |
| Traceability | Artifacts are stored under the Run ID, and reports and audit entries reference it |
| Communication | A Run ID is short enough to read aloud and paste into tickets; links such as `/runs/PF-2026-10-06-000127` open the run directly |
| Safety | Perfmon never stores aggregate performance metrics without a run. Ingestion requests without a resolvable Run ID are rejected |

## Format

```text
PF-YYYY-MM-DD-NNNNNN
│  │          └── global sequence number, zero-padded to 6 digits
│  └───────────── UTC date on which the run was created
└──────────────── fixed prefix "PF"
```

Example: `PF-2026-10-06-000127` is the run with sequence number 127, created on 6 October 2026 (UTC).

## How Run IDs are generated

- Run IDs are generated by the backend when a run is created (`POST /api/v1/runs`) and no custom `runId` is supplied.
- The number comes from a single database sequence (`run_number_seq`) shared by the whole installation. It does not restart each day, and it starts at 100 on a new installation. Numbers are unique and increasing, but gaps are possible (for example when a run creation transaction fails).
- The date part is the UTC date at creation time, not the start time of the test. A run created at 23:55 UTC and started after midnight keeps the earlier date.
- The number is zero-padded to six digits. Beyond 999999 it simply grows longer.
- Run IDs are never reused. Soft-deleted runs keep their Run ID.

## Custom Run IDs

You can supply your own identifier in `POST /runs`, for example to reuse a CI execution ID:

```bash
curl -s -X POST "$PERFMON_URL/api/v1/runs" \
  -H "authorization: Bearer $PERFMON_API_KEY" -H 'content-type: application/json' \
  -d '{"testId":"<test-id>","runId":"payments-nightly-2026-10-06"}'
```

Rules for custom Run IDs:

| Rule | Detail |
|---|---|
| Characters | Letters, digits, `.`, `_` and `-`; must start with a letter or digit |
| Length | 3 to 64 characters |
| Uniqueness | Must not exist yet, including deleted runs; otherwise `409 Run ID ... already exists` |

Note for JMeter: Perfmon can recognize a Run ID passed in the Backend Listener `application` tag only when it has the standard `PF-YYYY-MM-DD-NNNNNN` format. With custom Run IDs always pass `?runId=` in the listener URL (recommended in any case) or a `TAG_runId` parameter. See [JMeter Integration](09-jmeter-integration.md).

## Using Run IDs in the API

Every endpoint that takes a run accepts either the Run ID or the run's internal UUID:

```bash
curl -s "$PERFMON_URL/api/v1/runs/PF-2026-10-06-000127" -H "authorization: Bearer $TOKEN"
curl -s "$PERFMON_URL/api/v1/runs/8d0c6f8e-2f0e-4d64-9a51-7b1b0d1f0c11" -H "authorization: Bearer $TOKEN"
```

API responses expose both: `runId` is the Run ID and `id` is the UUID.

| Where the Run ID appears | Example |
|---|---|
| Run endpoints | `/api/v1/runs/PF-2026-10-06-000127/complete` |
| Ingestion | `/api/v1/ingest/influx/write?runId=PF-2026-10-06-000127`, `"runId"` field in `POST /api/v1/metrics` items and infrastructure payloads |
| Artifact storage keys | `projects/payments/tests/<test>/runs/PF-2026-10-06-000127/reports/...` |
| Artifact search | `GET /api/v1/artifacts?runId=PF-2026-10-06-000127` |
| Raw data exports | `PF-2026-10-06-000127-run_metrics.csv` |
| Events | `Test started (PF-2026-10-06-000127)` |
| UI routes | `/runs/PF-2026-10-06-000127`, `/live/PF-2026-10-06-000127` |

## Finding a run

- Testing → Test Runs (`/runs`): type the Run ID (or part of it) in the search box.
- API: `GET /api/v1/runs?q=PF-2026-10-06` matches Run IDs, test names, builds, commits, branches and tags.

## Access control

A Run ID is not a secret and does not grant access. Every request is still authenticated and authorized, runs of other organizations are reported as not found, and an API key bound to a project receives `403` for runs of other projects.
